# Практическая работа №2

### 1. Архитектура приложения

Программа построена по классической схеме game loop: события → ввод → обновление состояния → отрисовка → следующий кадр. Логика разделена на отдельные функции: `handle_events()` для обработки дискретных событий, `handle_movement(dt)` для непрерывного движения с delta time, `update_order(dt)` для обновления таймера приготовления, `draw_scene()` для отрисовки сцены, `draw_ui()` для отрисовки интерфейса, `draw_menu()` для отрисовки меню заказа.

### 2. Движение клиента

Используется `pygame.Vector2` для координат и направления. Движение нормализуется, чтобы диагональ не была быстрее осей: `if direction.length_squared() > 0: direction = direction.normalize()`. Скорость выражена в пикселях в секунду (240 px/s), перемещение зависит от `dt`, а не от FPS.

### 3. Столкновения и границы

Клиент не выходит за границы окна (ограничение через `max/min`) и не проходит через препятствия (прилавок, касса). Проверка выполняется для предполагаемой новой позиции: вычисляется `next_rect`, проверяется `colliderect` с препятствиями, и только если столкновения нет, позиция обновляется.

### 4. Зона взаимодействия

Перед прилавком создана невидимая логическая зона `interaction_rect`. Подсказка «E — сделать заказ» появляется только когда клиент находится внутри этой зоны. Нажатие `E` вне зоны ничего не делает.

### 5. Меню заказа

Меню открывается по `E` в зоне взаимодействия. Товары хранятся в списке словарей с полями name, price, stock, cook_time. Выбор осуществляется клавишами 1–4. Меню можно закрыть без покупки через `ESC`.

### 6. Состояния заказа

Используются четыре состояния: `NO_ORDER` (заказа нет), `WAITING` (готовится), `READY` (готов к выдаче), `DONE` (получен). Переходы: NO_ORDER → WAITING/READY → READY → DONE. Хлеб и булочка сразу переходят в READY, сэндвич и кофе — в WAITING.

### 7. Таймер без time.sleep()

Время приготовления уменьшается на каждом кадре через `dt`: `if order_state == WAITING: cooking_time_left -= dt`. Это позволяет приложению оставаться отзывчивым: клиент может двигаться, окно закрывается, FPS не падает.

### 8. Полоса прогресса

Для состояния `WAITING` рисуется двухслойный прямоугольник: серый фон и зелёная заполненная часть, ширина которой вычисляется как `bar_width * progress`, где `progress = 1.0 - cooking_time_left / total_cook_time`.

### 9. Обработка ошибок

Реализована проверка наличия товара (`stock > 0`), проверка бюджета (`money >= price`), вывод сообщений «Товар закончился» / «Недостаточно денег», корректное завершение по `Esc` и закрытию окна.
